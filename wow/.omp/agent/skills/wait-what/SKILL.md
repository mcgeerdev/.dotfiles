# Wait, what

Stop first. Never explain while still working.

Then decide which of the two cases you are in.

## The last message did not land

1. Name the one thing that probably did not land.
2. Pitch it again in plain English, using this project's vocabulary and none of the jargon you just used.
3. State what you had assumed the reader already knew.
4. Ask which part to expand.

## The work has run ahead of the user

1. Stop making tool calls. Report before touching anything else.
2. State the goal you are working towards, in one sentence.
3. List what you have already changed, file by file, and what is still untouched.
4. State what you were about to do next, and why.
5. Say which of those changes are reversible, and how.
6. Wait for direction. Do not resume on your own.

## Rules

- Do not repeat the same sentence more slowly. Change the framing.
- Add no new information until the gap is closed.
- One concept per attempt.
- Claim no progress you have not verified. "Wait" often means the user has spotted something wrong.
- Answer in plain prose. This is the wrong moment for tables, diagrams or jargon.
