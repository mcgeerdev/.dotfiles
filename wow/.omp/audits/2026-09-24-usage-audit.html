4. Where you can use omp better

4.1 Put a ceiling on the advisor largest cost

The advisor catches real mistakes. In September it told the main agent that a Kubernetes check had hit the wrong cluster, and that a PR it wanted you to approve was already merged:

#956 is already MERGED, verified via read(pr://956), updated 14:58:45Z. Empty reviewDecision/UNKNOWN mergeState did not mean an outstanding approval blocker.

The cost comes from a few runaway transcripts. On 2026-08-31 you asked research questions about moving cloudapi-dev to Cloudflare. No code changed. The advisor still made 1,325 globs, 706 reads and 706 greps for 16 notes, which comes to $42.69 per note against the $0.61 average. It read 787 M cached tokens to do it.

What to do:

  • Run /advisor off for research and Q&A sessions. The Doctrine remit covers code changes, and a Cloudflare cost discussion has none to review.
  • Watch the (adv) figure in the status line. omp 18.2.1 added a primary plus advisor split to the cost segment, and your status line already shows cost. /advisor status gives per-advisor tokens and cost.
  • Pin the advisor to medium effort in WATCHDOG.yaml and cap notes (see section 7).
  • Take the next omp release. The Unreleased changelog fixes "the advisor replaying the whole main transcript after the main session's per-turn prune" (#13131) and an extra request after advise-only turns (#13132). Both would inflate cache reads like the ones above [INFERENCE: I did not reproduce the replay].

4.2 Use plan mode instead of typing "don't make changes"

169 prompts carry a guard like "don't make any changes", "read-only" or "simply answer my question". The rate went from 29 of 1,115 prompts in July (2.6%) to 46 of 805 in August (5.7%) and 93 of 1,153 in September (8.1%). 110 of them are in tofu and its worktrees. You opened /plan 12 times, and omp injected plan-mode context 20 times.

What do you call it when the cache space runs out? what happesn to the images? Simply answer my question...... NO CHANGES,
don't make any more code changes just keep answering my question

Plan mode enforces what you are typing. omp's plan-mode guard restricts write, and subagents spawned under plan mode get only read, grep, glob and web_search. Toggle it with Alt+Shift+P before a question, and again when you want the change made. For tofu, where most guards happen, consider plan.defaultOnStartup: true in ~/didx.projects/tofu/.omp/config.yml. omp only reads project config from the launch directory, so worktrees and sites/* need their own copy.

5. Recurring patterns in how you work

5.1 Questions and instructions arrive in the same breath

612 prompts end with a question mark. Some also carry an instruction, and then the agent tends to act on it. You dictate by voice, which you said in a Codex prompt ("I am using voice dictation, never assume and ask if something is not clear"). That adds a second failure mode: mishears like "Mies" for mise, "OMYPI" for omp and "siteal services". 9 prompts open with "I meant", e.g. "I meant dynacat" after "I want attentiond to feed into glance".

Okay, a theoretical question. How does the minimum release age in renovate affect and work with the minimum release ages of the other package managers like Mies and whatever. I only want the minimum release age of renovate to affect renovate itself.

The first sentence says question. The last sentence reads like a requirement. The agent went off to research it, and your next prompt was the guard anyway. A one-word lead fixes this: start with "Question:" or "Change:", or flip plan mode first (4.2). For dictation, see the glossary idea in section 8.

10. Method

  • Costs, tokens, models and tool counts come from stats.db aggregates. Session counts come from top-level transcript files. The stats table also counts advisor and subagent files as sessions, so its count(distinct session_file) is higher.
  • I classified prompts with regexes over all 3,189 unique prompts in history.db. Duplicated prompts are stored once, so frequency counts for things like /quit run low. The patterns are in the audit transcript. Counts are approximate to within a few prompts.
  • "Blocks per 100 tool calls" divides Blocked: tool results in main and subagent transcripts by main-agent tool calls for the month. The July audit used a different window and counted only tool-preference blocks, so compare the trend, not its 1.2.
  • I read transcript excerpts from four sessions: didx-org 2026-08-31, wow 2026-09-17, attentiond 2026-09-12 and the tofu worktree 2026-09-22. The other quotes come from history.db prompts and advisor notes. The quotes are verbatim. None contained secrets. I left out a calendar URL and personal Codex topics.
  • The first version of this report said teach was used on 2026-09-23 and pr-diagram on 2026-09-15. Both came from word matches in history.db. I corrected them from the skill-prompt entries in the transcripts.
